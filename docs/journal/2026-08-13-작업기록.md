**리소스(CPU) 낭비**를, 어제 만든 **독립 프로세스 블랙박스 로그**로 진단해 해결했다.
남은 문제(호출버튼 방향 감지, 엘리베이터 문 타이밍)도 함께 기록한다.

## ✅ 해결한 것

### 1. 주행 중 "중간중간 멈춤" → CPU 타이밍 압박이 원인
**증상**: 승차지점 주행 중 잠깐씩 멈칫·정지 (실측 시각: 17:05 · 17:11 · 17:15 · 17:17 · 17:21 · 17:22 — 시나리오 시간대와 일치).

**진단** (nav 블랙박스 로그 `~/.ros/robot_diag/nav/`):
- controller_server: `Controller patience exceeded` 30회 → `Aborting handle` 44회 → behavior_server `Running wait`(=멈춤) 13회
- `Unable to transform robot pose into global plan's frame` 85회 (그 순간 map→odom 위치를 잠깐 잃음)
- **`Control loop missed its desired rate` 33회** ← 컨트롤러가 CPU에 밀렸다는 결정적 증거
- (참고: `map 프레임 없음` 537회는 **부팅 직후 16:59~17:04**, 초기위치 주기 전 startup 전이 — 멈춤 원인 아님)

**결론**: **CPU 타이밍 압박** → AMCL·컨트롤러가 제때 못 돌아 순간적으로 위치를 잃고 경로를 포기 → 멈춤.
- 엘베 과부하 아님: 멈춤이 엘베 ON 구간과 OFF 구간 모두에서 발생 (순차 운영은 제대로 했음).
- 중복 스택 아님: ROS 노드 35개 전부 고유, ros2 launch 1개 (중복 없음 확인).

### 2. 리소스(CPU) 낭비 → vision_assistant 상시 43%
**측정** (카테고리별 CPU):
| 프로세스 | CPU | 비고 |
|---|---|---|
| stretch_driver | 160% | 하드웨어 폴링 — 못 줄임 |
| 카메라(D435+D405) | 64% | nav·엘베에 필수 |
| nav 스택 | 81% | 필수 |
| **vision_assistant.py** | **43%** | ⭐ **불필요한 상시 낭비** |
| RViz | 16% | 생각보다 작음 |

**원인**: 카메라 콜백(`_cb`)이 body 카메라 **매 프레임(초당 15~30장)** 을 `cv2.imencode`(JPEG)+base64로
인코딩 — 실제론 **버튼 눌러 시각분석 할 때만** 쓰는 프레임을 상시 압축하고 있었음.

**해결** (commit `0ad773d`): 인코딩을 **매 프레임 → 요청 시(on-demand)** 로 변경.
- `_cb`: 최신 원본 msg만 보관 (거의 0% CPU)
- `get_frame_b64()`: 분석 요청 시에만 JPEG+base64 인코딩
- → **idle CPU 43% → ~0%**, 분석 품질 동일. 회수한 43%가 AMCL/컨트롤러로 → 멈춤 감소 예상.

### 3. 로그(블랙박스)로 진단 — 어제 만든 독립 프로세스가 빛을 발함
- **nav 블랙박스(robot_diag_nav, 독립 프로세스)** 가 주행 중 nav2 메시지를 전부 파일에 기록 →
  멈춤 시각·실패 메시지 원문을 사후에 정확히 분석 가능했다. (대시보드에 얹힌 옛 방식이었으면 못 잡았을 것)
- **하드웨어 감시기**(rplidar/driver 죽는 순간 시스템 상태 캡처)도 활용.
- 기록 위치: `~/.ros/robot_diag/{system,nav,elevator}/`

## ❌ 남은 문제 (미해결 — 다음 작업)

### 1. 호출 버튼 방향(▲/▼) 중 하나만 감지됨
- 상행(▲)/하행(▼) 호출 버튼 중 **하나만 인식**되어서, 오늘 시나리오가 **1층→5층(올라가기)만** 가능했다.
- 내려가기(▼)는 감지가 안 돼 시나리오를 못 돌림.
- → 버튼 인식/OCR 로직에서 **▲▼ 구분** 개선 필요 (버튼 맵 프로필·앵커 로직 점검).

### 2. 엘리베이터 문이 닫히기 전에 탑승 실패가 잦음
- 문이 열린 뒤 로봇이 **탑승 동작(전진 185cm)을 문 닫히는 시간 안에** 못 끝내는 경우가 많았다.
- → 문 열림 감지 후 **탑승 속도/타이밍 최적화**, 또는 **문 열림 유지 전략**(열림 버튼 누름 유지 등) 필요.
