# 층별 지도 도입 — 2026-11-11

5개 층이 한 장의 5층 지도(`all.pgm`)를 같이 쓰던 구조를 **층별 지도**로 바꿨다.
절차(재현 방법)는 `docs/NAVIGATION.md` 2.3 · 2.4, 결정 근거는 `.claude/DECISIONS.md` #39.

---

## 왜

`floor1~4.yaml`이 전부 `all.pgm`을 가리켜, 1~4층에서도 로봇은 5층 지도로 위치를 잡았다.
5층과 구조가 다른 곳에서 맞지 않는 부분이 있어 1~4층을 LIMO로 따로 맵핑했다
(LIMO **차번호 9313 · 상자번호 2715**, 사용법은 `docs/NAVIGATION.md` 2.3).

## 한 일 (순서대로)

1. **이름 정리** — `all` → `floor5`, LIMO 지도 `1~4` → `floor1~4`.
   옛 `floor1~4.yaml`(all.pgm 참조), `floor3/4.pgm`(all 사본), `floor3/4_backup_20260902.yaml` 삭제.
   launch 기본 지도 · `main.py _FLOOR_MAPS` · 캐빈 도구 사용 예시 경로를 `floor5.yaml`로.
   (같은 시점에 사용자가 `center` · `coex` · `test1~3_map` 지도를 정리함 — 코드 참조 없음 확인)
2. **LIMO yaml 경로 수정** — `image: /home/wego/Desktop/N.pgm`(절대 경로) → `image: floorN.pgm`.
3. **floor5로 빈 곳 채우기** — floor5를 각 층에 맞춘 정렬본을 만들고(`tools/map_align/align_to_floor5.py`),
   사용자가 GIMP로 필요한 부분(엘리베이터 캐빈, 빠진 복도 날개 등)을 붙였다.
   - 정렬 결과: 4층 5.9° · 3층 132.7° · 2층 -84.6° · 1층 -99.5° (floor5 → 각 층 회전)
   - 3층은 전체 기준 정렬이 엘리베이터 근처에서 **약 60 cm** 어긋나, 엘리베이터 주변만 다시 맞췄다.
   - **1층은 자동 정렬이 엘리베이터를 바로 위 화장실 자리에 맞췄다** — 사용자가 지적,
     후보 위치를 뽑아 사람이 1번(약 2.8 m 아래)을 골라 바로잡았다.
     → 도구가 후보를 자동으로 고르지 않고 사람이 `--pick`으로 고르게 만든 이유.
4. **검사** — 크기 · 형식 정상, 문앞↔캐빈 폭 60 cm 이상 연결(네 층 모두), 길 96~97%가 한 덩어리.
   흰색이 253(1·2층) · 255(3층)로 칠해져 있어 map_server 해석 그대로 254로 정리(동작 변화 없음 검증).
5. **floor5 좌표계로 옮기기** — 사용자 제안. 캐빈을 붙일 때 쓴 정렬의 역변환으로 1~4층 그림을
   돌리고 옮겨 origin을 다시 계산했다(`tools/map_align/reproject_to_floor5.py`, 변환값은
   `transforms_20261111.json`). 다섯 층 지도에서 캐빈 · 문앞이 같은 좌표에 오는 것을 겹침 그림으로 확인
   (`docs/images/floor-maps-elevator-check.png`).

## 결과로 바뀐 것

- `scene_targets.yaml`(엘리베이터 문앞 ②⑥ · 캐빈 ④) **한 세트를 다섯 층이 그대로 쓴다.**
- 캐빈이 모든 층 지도에서 같은 좌표라, 하차 때 지도를 바꿔도 캐빈 근처 AMCL 포즈가 유효하다
  (코드의 '하차 후 AMCL 재초기화 생략' 전제가 엘리베이터 근처에서 다시 성립).
- 엘리베이터에서 멀어질수록 다른 층과의 정렬은 어긋날 수 있다(층마다 구조가 달라 정상).
  각 층 지도 자체의 정확도는 그대로다.

## 남은 일 (이 순서로)

1. **로봇에 새 지도 올리기** (커밋 · pull 또는 maps 폴더 복사)
2. **층마다 위치 추정 확인** — 해당 층 지도로 바꾸고 복도를 돌며 레이저가 벽과 겹치는지.
   특히 **캐빈 안에서 다른 층 지도로 바꾼 직후 AMCL이 수렴하는지** (실기 미확인).
3. ~~호실 좌표 새로 따기~~ — **완료(같은 날).** 표시한 PDF를 배경으로 한 클릭 도구에서
   111곳(1층 12 · 2층 17 · 3층 27 · 4층 27 · 5층 28)을 찍고 방향까지 지정, 로봇 모양(뒤 0.98 m,
   왼쪽 0.56 m) 벽 여유 검사를 모두 통과. 5층도 새로 찍었다 — 예전 5층 506~512호는 방향 0°에서
   로봇 모양 왼쪽이 북쪽 벽에 걸렸다. 이름 규칙: `101호`, `316-1` → `316다시1호`,
   `504호(연구실)` · `520호(연구실)`, `107호(GS25)`, `공과대학 라운지`.
   엘리베이터 관련 좌표(문앞 · 하차지점 · 탑승지점)는 floor5 값을 그대로 쓴다.
   과정: 지도 PDF(격자 · 엘리베이터 확대)를 만들어 사용자가 호실 자리를 펜으로 표시 →
   그 PDF를 배경으로 한 클릭 도구에서 클릭 · 드래그(방향)로 찍고 JSON 저장 → 검사 후 반영.
   찍는 중 잡은 오타: 5층에 `403`·`420`(→ 504·520), 3층 `18`(→ 318), `503` 두 번(하나는 504).
   도구는 `tools/floor_points/`로 정리했다(`docs/NAVIGATION.md` 2.5). 표시 PDF · JSON을
   `tools/floor_points/data/`에 남겼고, `import_points.py`로 다시 만들면 지금 location.yaml과 똑같이 나온다.
4. **로봇 실주행으로 호실 좌표 확인** 전까지 1~4층 목적지 주행은 사람이 옆에서 지켜볼 것.
